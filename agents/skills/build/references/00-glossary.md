# Shape Up 术语表

> AI 代理参考手册。涵盖所有 Shape Up 文档中使用的术语。

## 核心概念

**Appetite（时间预算）**：分配给项目的会话数量。不是估算，而是驱动范围决策的创意约束。规模：Small Batch（1 个会话）、Medium Batch（2-3 个会话）或 Big Batch（4-5 个会话）。"会话"是一次专注的 AI 辅助工作对话。

**Baseline（基线）**：客户在没有该功能时的当前做法。用于判断"足够好"的比较基准。

**Bet（押注）**：承诺在分配的会话内投入资源完成项目，不中断，并期望完成。

**Betting Table（押注桌）**：利益相关者决定将哪些 Package 提交到会话的决策点。每次都是全新开始。

**Breadboard（面包板）**：一种 UI 概念，定义场所、功能点和连接，不包含任何视觉样式。使用文字和箭头，而非图片。

**Candidate（候选项）**：尚未被框架化的原始请求或想法。流程中的起始状态。

**Circuit Breaker（熔断器）**：默认策略：如果项目在分配的会话内未能交付，则取消（而非延期）。防止项目失控。

**De-Risk（去风险）**：从已塑形的工作中移除兔子洞和未知因素，以提高在分配会话内交付的概率。

**Discovered Tasks（发现的任务）**：团队在开始实际工作后才发现的任务。这些构成了任何项目的真正主体。

**Downhill（下坡）**：工作的执行阶段，所有未知因素已解决，只剩实现工作。

**Fat Marker Sketch（粗笔草图）**：用粗线条绘制的极低保真度 UI 草图，使细节无法呈现。当视觉布局是核心问题时使用。

**Frame（框架文档）**：框架化步骤产生的文档。包含问题、受影响的用户群、商业价值、证据和时间预算。参见 `08-framing.md`。

**Frame Go（框架通过）**：框架化后的审批关卡。意味着："这个问题值得投入。投入塑形时间。"授权塑形者花时间设计技术解决方案。

**Framing（框架化）**：塑形之前的正式步骤，调查问题、缩小范围并评估商业价值和紧迫性。回答："这个问题值得塑形吗？"参见 `08-framing.md`。

**Hill Chart（山丘图）**：一种可视化工具，显示工作状态从未知（上坡）到已知（下坡）再到完成的进展。

**Iceberg（冰山）**：后端工作远超 UI 复杂度（或反之）的范围。需要拆分为更小的范围。

**Imagined Tasks（想象的任务）**：团队在开始实际工作前基于思考认为需要的任务。通常不准确。

**Layer Cake（层叠蛋糕）**：UI 和后端工作均匀分布的范围。可通过 UI 表面积估算。

**Nice-to-Have（可选项）**：带有 `~` 前缀标记的任务。仅在时间允许时完成；如果没有时间则毫无愧疚地删除。

**Must-Have（必须项）**：范围被认为完成所必需的任务。在范围锤炼中保留。

**No-Go（排除项）**：在 Package 中明确声明的排除内容。故意不包含的功能。

**Package（方案包）**："Pitch"的演进术语。一份包含五个要素（问题、时间预算、解决方案、兔子洞、排除项）的文档，在押注桌上呈现。称为"Package"是因为业务方在框架化阶段已经认可——这不是销售提案，而是所有项目变量的完整捆绑包。

**Pitch（提案）**（旧术语）：参见 **Package**。原书使用"Pitch"，但 Ryan Singer 后来指出"pitching"更好地描述了框架化的输入（倡导某个问题值得关注），而非塑形的输出。

**Rabbit Hole（兔子洞）**：项目中过于未知、复杂或开放式的部分，在未解决之前无法安全押注。

**Raw Idea（原始想法）**：仅以文字表达的功能请求或想法。尚未塑形。默认回应："有意思，也许以后会做。"

**Scope（范围）**：项目中可以独立构建、集成和完成的部分。比任务大，比项目小得多。成为项目的工作词汇。

**Scope Hammering（范围锤炼）**：强力质疑每项工作，判断其是否真正值得在固定时间盒内投入时间。

**Shape Go（塑形通过）**：塑形后的审批关卡。意味着："解决方案可行，所有未知因素已解决。准备好进行构建承诺。"

**Shaping（塑形）**：通过定义关键元素、技术连接和风险，将已框架化的问题具体化的过程。发生在框架化之后。产出 Package。

**Small Batch（小批次）**：单会话项目。快速胜利和有限范围。

**Medium Batch（中批次）**：2-3 个会话的项目。适中范围，边界清晰。

**Big Batch（大批次）**：4-5 个会话的项目。重要功能或跨领域变更。

**Uphill（上坡）**：工作中仍存在未知因素和未解决问题的阶段。需要调查和解决问题。

## 塑形属性

已塑形的工作必须具备以下三点：

1. **Rough（粗糙）**：明显未完成。留有解释空间。防止过早承诺。
2. **Solved（已解决）**：主要元素在宏观层面相互连接。方向明确。已识别开放性问题。
3. **Bounded（有边界）**：定义了不做什么。团队在哪里停止。时间预算强制执行限制。
